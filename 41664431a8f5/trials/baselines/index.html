Baselines and approval

View as MarkdownOpen in ClaudeOpen in ChatGPT

A baseline is the approved result of one id: its state hash, frame count and, per platform, its frame hashes and images. Every trial run compares each result with scion/baselines/ and gives a verdict (same, within, px_changed, changed, new, stale). trial approve turns a run into the new baseline. Agents may approve only new; replacing a baseline someone approved needs a person at an interactive terminal.

When to use

Section titled “When to use”
  • Approve after an intended change, once the run shows exactly the change you meant.
  • Never approve to make a failure go away: a failed recipe cannot be approved.

Steps

Section titled “Steps”

1. Run and read the verdicts

Section titled “1. Run and read the verdicts”

2. Compare side by side

Section titled “2. Compare side by side”

--grid writes one image per artifact with three columns: baseline, current, difference.

3. Approve

Section titled “3. Approve”

approve writes the files and runs git add on them; it never commits.

Reference

Section titled “Reference”

Verdicts

Section titled “Verdicts”
Verdict When
same Hash, frames and images match.
within Images differ inside the recipe’s Tolerance.
px_changed Hash and frames match, frame hashes differ, and the recipe compares no images (Tolerance = null). Informative.
changed The hash differs, frames differ by more than one, an image is outside the tolerance, or the rule digest changed.
new The id has no baseline.json.
stale baseline.json exists but not for this platform, or fps, player args or Unity differ. Images and frame hashes are suspended; the hash is still compared, so a different hash is changed.

reasons lists what triggered changed: hash, frames, px, image, rule_hash. stale lists why: platform, fps, player_args, unity.

Who approves what

Section titled “Who approves what”
Verdict Agent (no TTY) Person at a terminal
new yes yes
changed, stale, within, px_changed no: exit 2, human_required yes, after a confirmation prompt
failed recipe no no
run with --grafts or --warm no no

Approval is all or nothing: if one id is refused, nothing is written and refused[] says why. The guard hook asks the person before an agent’s trial approve and denies edits under scion/baselines/ (Hooks).

Storage

Section titled “Storage”

Store PNGs with Git LFS. Approving on one platform updates baseline.json and that platform’s folder; other platforms become stale until someone approves on each.

Rule digest

Section titled “Rule digest”

rule_digest is a 12-hex digest of the files under rule_paths in scion.json (Assets/Orchard/Core, Assets/Orchard/Data), uncommitted changes included. When it differs from the baseline’s, the verdict is changed with reason rule_hash, even if the hash happens to match: a rule change must be reviewed.

Errors

Section titled “Errors”
Code Exit Cause Next action
human_required 2 Approval of a non-new verdict without a TTY. A person runs the command at a terminal.
refused 1 An id failed, or the run used --grafts or --warm. Fix it, run cold, approve again.
no_match 2 The id is not in the run. trial show lists the ids of the run.
warning not_staged 0 git add failed (no repository, LFS missing). Stage the files yourself.
