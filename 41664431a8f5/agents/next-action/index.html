What to do next

View as MarkdownOpen in ClaudeOpen in ChatGPT

Look up the exit code and the signal a Scion command returned, and do the action in the last column. The signals are the envelope fields (error.code, warnings[].code, failed[], changed[], vs_approved, determinism), the SCNxxx ids of diagnostics and the control-protocol errors. Every code links to its full entry in Error and warning codes, which is the single source for the exit code of each error. When two rows apply, handle the higher exit code first. Exit 0 is not always “done”: a changed verdict exits 0 with ok: true (ok and changed), so check changed[] too.

Exit 0

Section titled “Exit 0”
Signal Meaning Next action
warnings and changed[] empty, runs.new 0 Done. Follow next_step.
vs_approved: changed (in changed[]) Hash, frames (off by more than one), images outside tolerance or the rule digest changed. A review signal, not a failure. If intended: explain it with trial show --changed (and --grid) and ask a person to approve. If not: fix the code. Never approve it yourself.
vs_approved: same Hash, frames and images match the baseline. Nothing to do.
vs_approved: new The recipe has no baseline yet. Read its report.md; if it shows what the recipe should, dotnet scion trial approve --new --reason "..." and commit the staged files.
vs_approved: within Pixels differ, inside the recipe’s tolerance. Nothing to approve; only a person may refresh it. Mention it if the task was visual.
vs_approved: px_changed Pixel hashes changed for a recipe that keeps no images. Informative. Open window.png only if the task is visual; if intended, a person may approve it.
vs_approved: stale The baseline was approved on another platform, Unity version, fps or player arguments; images were not compared. Tell the person; a person approves on this platform when the result looks right.
warning build_stale Sources or rule files changed after the build. dotnet scion build test, then run again before trusting the result.
warning build_info_missing No scion-build.json next to the build. dotnet scion build test.
warning frame_jitter A frame count is one off its baseline (allowed). Nothing; if it repeats, see Verify determinism.
warning px_unstable Pixels vary between rounds of this run. Treat px_changed as noise; see Particles, animators, UI and physics.
warning low_memory Fewer copies fit in free RAM than requested. Use suggested_copies from doctor for -j.
warning version_mismatch CLI, package and plugin versions differ. Update the one the message names.
warning recycle A warm copy loaded 50 graft DLLs. dotnet scion trial serve --stop, then trial serve again.
other warnings Something did not stop the command. Read its entry in Error and warning codes.

Exit 1

Section titled “Exit 1”
Signal Meaning Next action
failed[] A (recipe, round) failed: timeout, Fail, a check, a logged error, a graft that threw. Read failed[].report; fix the cause; run again.
determinism.hash_stable: false Rounds of one recipe disagree, or no round passed. Check failed[] first. Then dotnet scion trial run <Id> --rounds 4 --check; read determinism.tsv; see Verify determinism.
refused in trial approve A selected recipe has a failed round, an unstable hash or was run with --grafts. Nothing was written. Fix that recipe; next_step gives the command that approves the others.
diagnostics[] in graft check or graft build Graft errors with SCN ids. Apply each hint and did_you_mean; check again.
errors[] in build test Compiler (CSxxxx) or Scion (SCNxxx) errors. Fix the file and line; build again.
SCN130 in graft inject or trial run --grafts The graft DLL was built for another build. Nothing was injected. dotnet scion graft build, then inject again.
SCN131 in graft inject or trial run --grafts The graft DLL or the build has another Scion ABI. Nothing was injected. Use the same Scion version for the CLI and the build.
spec.ok: false in trial run --spec An expectation of the spec failed. Read spec.json; never edit the spec to make it pass.

Exit 2

Section titled “Exit 2”
Signal Meaning Next action
usage, unknown_command, unknown_option, bad_value Wrong call. Use did_you_mean and error.hint, or <command> --help. Never retry unchanged.
no_match No recipe, run or anchor with that name. dotnet scion trial list (or anchor list); use did_you_mean.
human_required The approval replaces a baseline a person approved, and there is no terminal. Stop. Tell the person what changed and the exact command from next_step. Never fake a terminal.
not_supported The build lacks the define the command needs (control op without SCION_SLOTS or SCION_TRIALS). dotnet scion build test.
missing_out, unknown_flag A player started by hand got a bad command line. Fix the -scion-* flags; see Player command line.

Exit 3

Section titled “Exit 3”
Signal Meaning Next action
config_not_found No scion.json above the current folder. cd into the project, or dotnet scion init.
config_invalid A bad key, type or JSON line. Fix the key the message names; validate with scion-config.schema.json.
build_not_found, build_wrong_mode No usable test build. dotnet scion build test.
unity_not_found The project’s Unity version is not installed. Install it, or set unity.editor in scion.local.json.
editor_open The editor holds the project and has no com.unity.pipeline. Close the editor, or add com.unity.pipeline to the project.
unity_failed Unity ended without building and without a compiler error. Read the log named in the message.
player_crashed, copy_timeout, watchdog A copy died or stalled. Read q<i>/player.log; rebuild if the build is old; raise --timeout only for slow recipes.
no_adapter, prepare_failed No valid adapter, or an adapter’s Prepare failed. Read error.message (it names SCN202 or SCN203 when relevant) and the player log.
capture_broken Frame capture failed. Read the player log; run once with --window to compare.
out_not_writable, no_free_port The machine blocks the run. Fix permissions or trials.out; close programs that hold ports, or use fewer copies.
shard_ignored Two copies ran the same (recipe, round): the build ignores -scion-shard. dotnet scion build test, or run with -j 1.
no_copies graft inject, --warm or trial loop found no warm copy. dotnet scion trial serve -j 2.
no_simulation, not_forkable A level 3 command without an ISimulation. Register one; see Add Scion to an existing game.
mosaic_unsupported --mosaic with an adapter that is not an IMosaicAdapter. Run without --mosaic, or see Mosaic.
model_missing The eye model of the Judge is not in the model cache, or a needed head is not trained. dotnet scion judge model pull (the error.hint names the eyes), then run the command again; for a head, ask a person to train it. See Models and licenses.
SCN202, SCN203 Invalid adapter, or two adapters for one recipe type. Fix the adapter as the hint says.
interrupted Ctrl-C or a cancelled MCP call stopped the command. Run it again.
internal_error A bug in Scion. Report it with the stack trace; do not loop.

Exit 125

Section titled “Exit 125”
Signal Meaning Next action
A bisect step The step cannot be judged: the build, the recipe or its rounds broke at that commit. Nothing: bisect skips the commit and goes on.

Control protocol

Section titled “Control protocol”
Signal Meaning Next action
busy A queue is already running in that copy. Wait for it, or send quit.
bad_token Wrong or stale token. Re-read control.json of that copy.
not_supported The copy lacks SCION_SLOTS or SCION_TRIALS. Rebuild with dotnet scion build test.
bad_json, line_too_long, unknown_op, bad_args, shutting_down A malformed request, or the copy is quitting. Fix the request; see Control protocol.

Diagnostics

Section titled “Diagnostics”
Signal Next action
SCN001-SCN005 Standard warnings and SCN003 (error). Standard diagnostics.
SCN101-SCN114 Graft errors; apply the hint. Graft diagnostics.
SCN120-SCN131 Build mode and injection. Build and injection diagnostics.
SCN201-SCN203 Recipes and adapters. Trials diagnostics.
SCN301-SCN307 Determinism scan, in diagnose only. Determinism diagnostics.
