For AI agents

View as MarkdownOpen in ClaudeOpen in ChatGPT

This is the start page for AI coding agents (Claude Code, Codex, Cursor, GitHub Copilot and others) that work on a game with Scion. It gives the loop (graft check, graft inject, trial run, trial show, trial approve --new), the rules every agent must follow, the reading order that keeps token use low, and the machine-readable files: llms.txt, the Markdown twin of every page, the JSON Schemas and the docs inside the installed package.

When to use

Section titled “When to use”
  • Read this page before your first Scion command in a project, and whenever a command’s result surprises you.
  • For one exit code or error code, go straight to What to do next.

Rules

Section titled “Rules”

These rules are also at the top of /scion/llms.txt. Follow them in every session:

  • Run dotnet scion doctor first. Exit 0 means usable; exit 3 means fix what error.hint says.
  • Every command prints one JSON object on stdout (schema_version, ok, next_step, error on exits 2 and 3). Parse it; do not scrape text. Follow next_step.
  • Exit codes: 0 ok, 1 a check failed, 2 usage error (see did_you_mean), 3 environment. Next actions: https://jand-s.github.io/scion/41664431a8f5/agents/next-action.md
  • You may approve only new baselines (trial approve --new --reason "..."). Never approve changed, stale or px_changed, and never edit scion/baselines/ by hand: ask a person.
  • Read report.md only for failed or changed recipes; open images only when pixels changed or the task is visual.

Two more that follow from the design:

  • Grafts are visual only. A change to damage, range, turn order or any other rule goes into the game’s core as a RuleModifier<T>, never into a graft (Grafts are visual only).
  • Never fake a terminal (script, expect, a pseudo-TTY) to get past human_required. Tell the person what changed and give them the command from next_step.

Steps

Section titled “Steps”

1. Orient yourself

Section titled “1. Orient yourself”

index prints the project index (under 2 KB): Scion version, adoption level, graft folders, anchor categories, recipe names and the commands. With the Claude Code plugin it arrives on its own at session start.

2. Find where to hang the change

Section titled “2. Find where to hang the change”

anchor show returns the signature and a ready graft declaration (example). Never guess a signature.

3. Write and check the graft

Section titled “3. Write and check the graft”

Apply every hint and did_you_mean until graft check exits 0. With the plugin, the PostToolUse hook runs the check after each edit and returns the errors to you.

4. Try it in the real build

Section titled “4. Try it in the real build”

Warm runs compare state hashes and frame counts. For images, run a cold run with the graft: dotnet scion trial run SlashHit --grafts <dll from graft build>.

5. Read the results

Section titled “5. Read the results”

Follow Reading results: the JSON, then report.md of failed or changed recipes, then images only when pixels changed or the task is visual.

6. Hand over

Section titled “6. Hand over”
  • New recipes: dotnet scion trial approve --new --reason "...", then commit the staged baselines.
  • Changed recipes: stop and report. Give the person trial show --changed output, the reason and the exact approve command from next_step.
  • Promote a graft only when the person agrees: dotnet scion graft promote CritShake.

Version-matched local docs

Section titled “Version-matched local docs”

The installed package carries the Markdown of its own version. Prefer it over the website when the project may not run the latest version:

dotnet scion mcp serves the same files through its docs_search and docs_read tools.

Token budget

Section titled “Token budget”
Read Cost
A command’s JSON under 1.5 KB, always
report.md of one recipe about 1,200 tokens
window.png (12 frames) about 1,000 tokens
context.png (6 frames) about 1,900 tokens
120 captures opened blindly about 1 million tokens: never do this

With more than about 5 images to look at, hand them to the scion-triage subagent, which returns one line per recipe (The Scion skill).

Errors

Section titled “Errors”
Signal Next action
Exit 1, failed[] Read failed[].report, fix, run again.
Exit 1, changed[] Explain the change with trial show --changed; ask a person to approve or fix it.
Exit 2 Fix the call with error.hint and did_you_mean; never retry unchanged.
Exit 3 Fix the environment with error.hint; doctor names the failing check.

Every signal, with its exact next action: What to do next.
