# index, guard

`dotnet scion index` prints a project index under 2 KB: the Scion version, the adoption level, the grafts folders,
anchor categories, recipes and the commands that matter, for an agent's session start. `dotnet scion guard` decides
whether an agent's action on baselines or generated files is allowed, needs a person, or is denied. Both have a
`--hook` mode that speaks Claude Code's hook format.

## Synopsis

```text
dotnet scion index [--hook] [--write <file>]
dotnet scion guard [--approve] [--hook] [--path <file>] [--command "<cmd>"]
```

## Description

Both commands are fast (well under a second), read only local files and never start Unity, so agent hooks can call
them on every session and tool use.

## index

Builds the index from `scion.json`, the manifest (or the build) and the baselines. With `--write <file>`, keeps the
index and the agent rules between `<!-- scion:begin -->` and `<!-- scion:end -->` in `CLAUDE.md` or `AGENTS.md`,
leaving the rest of the file alone. With `--hook`, wraps it as `hookSpecificOutput.additionalContext` for
`SessionStart`.

## guard

| Situation | Decision |
|---|---|
| An edit or write under `scion/baselines/` | `deny`: only `trial approve` writes baselines. |
| An edit of `scion.manifest.json` or `GRAFTS.md` | `deny`: generated by `gen`. |
| `trial approve` of ids that are only `new` | `allow`. |
| `trial approve` that would replace a baseline (`--approve`) | `ask`, with what changed and the review command. |
| Anything else | `allow`. |

With `--hook`, `guard` reads the hook input from stdin (tool name, path, command) and prints
`hookSpecificOutput.permissionDecision`. Every hook finishes under one second and fails open, except the baselines
guard, which fails closed.

## Options

| Option | Commands | Meaning |
|---|---|---|
| `--hook` | both | Claude Code hook input and output. |
| `--write <file>` | index | Maintain the block in an instructions file. |
| `--approve` | guard | Check a `trial approve` command. |
| `--path <file>` | guard | Check an edit of this path (without `--hook`). |
| `--command "<cmd>"` | guard | Check this command (without `--hook`). |

## Exit codes

| Code | When |
|---|---|
| 0 | Printed (a `deny` is still exit 0 in hook mode; the decision is in the JSON). |
| 2 | Bad option. |

## Errors

| Code | Exit | Cause | Next action |
|---|---|---|---|
| `config_not_found` | 0 in hook mode | Not a Scion project. | The hooks do nothing outside Scion projects. |
| `usage` | 2 | `guard` without `--hook`, `--path` or `--command`. | Pass one. |

## Examples

### Keep CLAUDE.md current

```sh
dotnet scion index --write CLAUDE.md
```

### Test the guard by hand

```sh
dotnet scion guard --command "dotnet scion trial approve --changed --reason x"
```
