Quickstart

View as MarkdownOpen in ClaudeOpen in ChatGPT

This tutorial takes about ten minutes on the Orchard Tactics sample. You build the test player with dotnet scion build test, run the SlashHit recipe with dotnet scion trial run, approve its first baseline, write the HitFlash graft, inject it into a running copy with graft inject, promote it, and review the changed verdict it causes. You finish with a second recipe of your own.

Before you begin

Section titled “Before you begin”
  • Scion is installed: package, CLI and dotnet scion doctor passing (Install).
  • An empty Unity 6000.3 project in a git repository, with the CLI tool manifest. The commands below create the Orchard sample in it:

new --genre tactics writes the Orchard game skeleton (Assets/Orchard/Core, Runtime, Grafts, Trials), a battle scene, the OrchardAdapter, the SlashHit recipe, scion.json and the agent block in CLAUDE.md (Start a new project).

Steps

Section titled “Steps”

1. Build the test player

Section titled “1. Build the test player”

The test build is a Mono player with the SCION_SLOTS and SCION_TRIALS defines. With the editor open the CLI builds through it when the project has com.unity.pipeline; otherwise close the editor first (editor_open).

2. Run the sample recipe

Section titled “2. Run the sample recipe”

Both rounds passed and agree on the state hash (hash_stable: true). new: 1 means SlashHit has no baseline yet.

3. Read the result

Section titled “3. Read the result”

The output names report.md and the images. Read report.md first: the verdict, the checks, the timeline of marks and the probes. Open window.png (12 frames around the impact) only to look at the effect itself.

4. Approve the first baseline

Section titled “4. Approve the first baseline”

trial approve writes scion/baselines/SlashHit/ and stages it with git add; it never commits. Anyone, including an AI agent, may approve a new recipe. The next run of SlashHit reports same.

6. Try it live in a running copy

Section titled “6. Try it live in a running copy”

Start one warm copy, compile the graft against the build, inject it and replay the recipe:

The copy keeps running between commands, so each edit-build-inject-run cycle takes about a second. The flash is visual only: the state hash stays the same as the baseline.

7. Promote the graft

Section titled “7. Promote the graft”

graft promote moves the file to Assets/Orchard/Grafts/HitFlash.cs, where it compiles into the game. The run now compares the images with the baseline and finds the flash:

Exit code 1: SlashHit is changed. The rules did not change (hash: same); the image did, outside the tolerance.

8. Review and approve the change

Section titled “8. Review and approve the change”

--grid writes grid.png with three rows: the baseline, the current frames and the difference. If the flash is what you wanted, a person approves it at an interactive terminal:

An AI agent cannot do this step: without a terminal the CLI stops with human_required. That is the point: a result a person approved is only replaced by a person.

Check the result

Section titled “Check the result”
  • dotnet scion trial run exits 0 and reports same for SlashHit and KnightFalls.
  • scion/baselines/ holds both recipes, committed.
  • Assets/Orchard/Grafts/HitFlash.cs is in the game; dotnet scion build final builds the shipping player with the flash as a direct call.
