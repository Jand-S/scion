# Rules R1-R8

Each rule below has a statement, the reason, an example from Orchard and how Scion checks it. Rules are numbered for
reference in reviews and in agent instructions ("this breaks R3"). Analyzer ids are in
[SCN001-SCN005](/scion/41664431a8f5/reference/diagnostics/standard/).

## R1 Inherit one level from a Scion base, sealed

**Why.** The base controls the flow (Template Method), so subclasses cannot get it wrong, and `sealed` lets IL2CPP
devirtualize calls.

```csharp
public sealed class OrchardAdapter : TrialAdapter<OrchardRecipe> { /* ... */ }
public sealed class BackstabBonus : RuleModifier<DamageCalc> { /* ... */ }
public sealed class HudStates : StaticTrial<HudState> { /* ... */ }
```

**Enforced by** SCN001 (not sealed) and SCN002 (more than one level) in rule code.

## R2 Anchors take values, not services

**Why.** An anchor method whose parameters are plain values (`HitEvent`, `int turn`) gives grafts everything they
need without reaching into services, and keeps grafts testable with `new Call<T>(...)`.

```csharp
public float Play(HitEvent e)   // HitEvent is a readonly struct: attacker, target, amount, crit
```

**Enforced by** review and the exemplars; `anchor show` prints the signature grafts bind to.

## R3 Rules that change numbers are RuleModifier

**Why.** A rule change registered explicitly with a stage, a priority and integers is visible, ordered and the same
on every peer. A graft that changed it would vanish outside Unity.

```csharp
public sealed class BackstabBonus : RuleModifier<DamageCalc>
{
    public override Stage Stage => Stage.Mul;
    public override int Priority => 10;
    public override void Apply(ref DamageCalc c) { if (c.FromBehind) c.MulPermille += 500; }
}
```

**Enforced by** SCN003 (a graft writes rule state), SCN004 (`float` in rule code: use `int` or permille so every
machine computes the same result) and the hash A/B run.

## R4 New content is a Type Object plus a strategy by enum

**Why.** A new ability is a data row and one case in a strategy, so completeness can be tested: every enum value has
a handler.

```csharp
public enum AbilityEffect { Damage, Heal, Push }
public static int Resolve(AbilityEffect e, ref DamageCalc c) => e switch
{
    AbilityEffect.Damage => Damage.Apply(ref c),
    AbilityEffect.Heal => Heal.Apply(ref c),
    AbilityEffect.Push => Push.Apply(ref c),
    _ => throw new ArgumentOutOfRangeException(nameof(e)),
};
```

**Enforced by** completeness tests generated by `scion new effect`.

## R5 Interfaces only for context and optional capabilities

**Why.** Interfaces such as `ISaveable` or `IMirrorable` say what the state can do; using them for everything adds
indirection without value. Serialized types avoid `record` and `init`, which Unity's serializer does not support.

**Enforced by** review and `doctor`'s capability report.

## R6 Every mutation is a Command

**Why.** Commands can be logged, replayed, captured with F9, forked in the multiverse and sent over the network.
Event dispatch is a `switch` calling named methods, and those methods become anchors.

```csharp
battle.Issue(Command.Ability("slash", attacker: 0, target: 1));
```

**Enforced by** level 3 requirements: `ISimulation.Apply(command)` is the only way to change state.

## R7 The adapter is a Template Method

**Why.** One public, non-virtual entry point per job (build state, apply a command, hash) keeps adapters small and
the same across games.

**Enforced by** `TrialAdapter<TRecipe>` and the skeleton `diagnose --adapter` writes.

## R8 Helpers by composition

**Why.** A thin facade object (`Fx`) gives every graft the same verbs without a fat base class. Extension methods
only on struct contexts.

**Enforced by** the `Fx` facade and the exemplars.
